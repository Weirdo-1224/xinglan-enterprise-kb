# 项目管理制度

## 1. 目的、对象与触发

规范从商机转项目、立项、规划、执行、监控、验收、结项和复盘的全生命周期；适用于四类项目及其售前、研发、交付和支持活动。

## 2. 职责分工

项目经理对范围、计划、协同和项目证据负责；项目交付中心提供资源与质量管理；PMO 维护方法、检查重大节点和组合风险；产品研发、市场、采购、财务、法务按专业职责审查；授权负责人决定立项、重大变更和关闭。

## 3. 领域规则

- 启动前明确客户目标、合同边界、需求基线、验收指标、预算和项目经理；事实不足的商机不得直接包装为已承诺项目。
- WBS 拆到可分工、可估算、可验收的工作包，里程碑必须对应决策或可核验成果，不以会议日期替代完成条件。
- 范围、进度、成本、质量、资源、风险和干系人计划采用同一基线，责任人定期报告预测而非只报告已发生情况。
- 项目问题记录已发生偏差及处理，风险记录未发生事件的概率、影响、应对和触发器，两者不得混用。
- 交付物进入客户环境前完成技术、数据、安全和合同检查；未满足前置条件不得以赶工为由跳过。
- 验收依据合同和经批准的需求/变更，结项还须完成回款与成本核对、资料归档、未决事项移交和复盘。

## 4. 审批与关键控制点

- 立项门核对商业目标、合同状态、预算、资源、风险和治理级别。
- 周度或阶段监控使用基线与实际/预测对比，偏差指向明确的纠偏、变更或升级路径。
- 重大节点的批准人与项目执行者保持必要分离，客户确认只由有权窗口取得。

## 5. 例外、停止与升级

- 售前验证或短期试点可采用精简计划，但必须定义数据边界、成功标准、退出条件和费用责任。
- 出现合同未生效、关键资源无着落、客户前提不成立、L4 风险或交付证据失真时停止受影响工作并升级。

在项目管理事项中，需要跨部门裁决或达到 L3 风险时交对应职能负责人/PMO；违法、安全、舞弊或 L4 重大风险立即停止受影响活动，保全原始证据并升级总经理办公会或授权负责人。例外批准必须限定事项、理由、期限和补救，不能变成长期默认做法。

## 6. 记录与归档

立项材料、需求与范围基线、WBS/进度、预算成本、资源计划、风险问题、周报、变更、评审、交付验收、回款和复盘记录。客户与安全资料按合同和分类分级归档。
