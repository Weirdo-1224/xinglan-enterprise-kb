# 银行企业知识助手项目-需求调研记录

本文件为星澜数字科技有限公司合成历史项目材料（SYNTHETIC），不代表真实企业或真实事件。

## 1. 售前调研（2024-01-16 至 2024-01-29）

按 SOP001 客户需求澄清流程，解决方案顾问在客户信息科技部陈恪协调下完成售前调研（EVT-P002-002），调研记录要点如下。

### 1.1 调研对象与方法

- 访谈部门：信息科技部、运营管理部、零售金融部、公司金融部、合规部。
- 调研方法：结构化访谈 9 场，收集行内制度文件、产品手册、操作指引样例约 300 份，观察柜面与客服知识检索操作 2 次。
- 参与人员：我方解决方案顾问、客户方陈恪及各部门业务骨干。

### 1.2 售前调研确认的需求要点

| 编号 | 需求要点 | 来源部门 |
|---|---|---|
| SR-01 | 自然语言问答，回答附原文出处与引用 | 信息科技部 |
| SR-02 | 首期覆盖制度、产品、操作指引三类知识 | 信息科技部 |
| SR-03 | 权限随行内组织架构，支持按部门与岗位可见性控制 | 信息科技部 |
| SR-04 | 柜面高频业务场景的产品要素问答 | 零售金融部 |
| SR-05 | 对公业务产品说明与流程指引问答 | 公司金融部 |
| SR-06 | 合规文件版本管理与生效日期提示 | 合规部 |
| SR-07 | 私有化部署，行内数据不出域 | 信息科技部 |

### 1.3 售前遗留分歧

零售金融部与公司金融部提出将信贷业务知识纳入首期范围，合规部提出纳入监管合规矩阵知识；陈恪在调研总结会上表示"知识域边界需在立项后由行内统一确认"。该分歧当时未关闭，成为项目启动后需求基线无法按期冻结的根源（EVT-P002-008）。

## 2. 启动后需求持续补充（2024-03-11 至 2024-05-10）

项目于 2024-03-11 启动（EVT-P002-006）。启动后，客户多个业务部门持续通过陈恪提交补充需求：

- 2024-03-18：运营管理部补充柜面操作类知识条目约 800 条。
- 2024-03-27：零售金融部提交零售信贷产品问答场景 3 类。
- 2024-04-02：合规部要求回答引用携带文件版本号。
- 2024-04-11：公司金融部提出对公票据业务知识纳入诉求。
- 2024-04-19：陈恪组织行内需求碰头会，各部门对知识域范围意见不一，需求基线无法冻结（EVT-P002-008）。

## 3. 基线延期原因分析

需求基线原计划 2024-04-15 冻结，实际 2024-05-10 才确认，延期 25 天（EVT-P002-009）。直接原因是行内各部门对信贷、票据知识域是否进入首期范围长期不一致，知识工程负责人孟婕与项目经理周骁组织了 4 轮澄清会（4-22、4-26、4-29、5-07）才达成一致。范围迟迟不定使设计开发与知识加工并行节奏被打乱，为变更 P002-CH01（2024-05-20 客户追加信贷、合规、票据三类知识域）埋下了直接诱因。
