# 培训管理制度

## 1. 目的、对象与触发

适用于入职、岗位技能、管理、合规与项目复盘等培训活动，覆盖需求识别、课程设计、实施、考核、效果转化和资料归档。

## 2. 职责分工

人力资源中心制定培训计划和质量标准；部门负责人确认岗位差距与参训人；讲师或内容责任人保证材料正确；员工完成学习与实践；信息安全、法务等专业部门审核其控制领域课程。

## 3. 领域规则

- 培训需求必须来自岗位能力差距、制度变化、项目复盘或风险事件，不能仅以报名人数替代需求分析。
- 课程目标写明培训后可观察的行为或产出，并区分必修、选修、上岗前置和复训。
- 引用客户资料、代码、案例或外部课程时先核验保密、著作权和授权范围；敏感样例应脱敏并限制下载。
- 考核方式与目标匹配：知识类可测试，操作类须实操或作品验证，管理类关注情境决策与后续行为。
- 培训完成不等同能力达标；需由主管在实际任务中验证应用，未达标者安排辅导、补训或调整任务。

## 4. 审批与关键控制点

- 开课前审核讲义版本、讲师资格、参训范围和数据分类。
- 签到、学习时长或测验只作为过程证据，效果评价至少关联岗位行为或交付变化。
- 课程失效、规则更新或发生误导性内容时立即停用旧版本并通知已参训人员。

## 5. 例外、停止与升级

- 紧急制度宣贯可先采用短课和确认回执，后续补充案例与考核；不得因此省略关键风险提示。
- 外部证书或他企培训经历只作能力证据之一，是否胜任仍由岗位实际任务验证。

在培训绩效事项中，需要跨部门裁决或达到 L3 风险时交对应职能负责人/PMO；违法、安全、舞弊或 L4 重大风险立即停止受影响活动，保全原始证据并升级总经理办公会或授权负责人。例外批准必须限定事项、理由、期限和补救，不能变成长期默认做法。

## 6. 记录与归档

培训需求、年度/专项计划、课程目标、审核版本、参训与考核记录、实践验证、反馈改进和停用记录。员工学习数据仅向培训管理者、本人及有管理需要的主管开放。
