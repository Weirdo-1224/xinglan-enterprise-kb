# 知识产权与保密管理制度

## 1. 目的、对象与触发

适用于软件代码、算法模型、数据集、文档、方案、商标、专利、开源组件、第三方素材及员工/供应商创造的成果，覆盖获取、使用、交付、许可、公开和离职交接。

## 2. 职责分工

成果创建者标识来源和贡献；项目/产品负责人维护成果清单及交付范围；法务风控判断权属、许可和保密；采购审查第三方授权；技术负责人管理代码依赖和模型/数据来源；对外发布人核验批准与脱敏。

## 3. 领域规则

- 立项或签约时明确背景知识产权、项目新成果、第三方材料、许可范围、署名、改进成果和退出后的使用权。
- 受著作权保护的软件、文档和其他作品的复制、修改、传播或信息网络传播须具备许可或法定依据，不能因网络可访问就默认可用。
- 开源组件记录名称、版本、许可证、修改和分发方式；强互惠、专利或署名义务与交付模式冲突时先由法务和技术评估。
- 训练/评测数据、模型权重和提示资产记录来源、授权、用途、期限及可交付性；客户数据未经合同和授权不得用于通用训练。
- 商业秘密按非公开性、商业价值和保密措施管理，接触人员限于任务所需；对外演示、论文、代码仓库和投标材料发布前脱敏审查。
- 员工或供应商离项时完成账号、代码、设备、文档和第三方资料交接，持续保密义务按合同和法律执行。
- 侵权通知或权属争议出现时停止新增传播，保全版本、来源、许可和贡献证据，未经审查不承认或否认责任。

## 4. 审批与关键控制点

- 代码仓库、模型登记和交付清单建立来源字段与许可证扫描，未知来源项不得进入正式发布。
- 合同审查将知识产权、保密、数据和成果交付与项目验收条件对应。
- 对外内容由业务、技术和法务按风险共同确认，批准仅覆盖明确版本与渠道。

## 5. 例外、停止与升级

- 开源或公开资料只能按许可证/使用条款使用，公开不等于放弃权利。
- 来源无法证明、许可范围不清、客户要求与第三方条款冲突或疑似商业秘密泄露时停止使用并升级。

在信息安全数据治理事项中，需要跨部门裁决或达到 L3 风险时交对应职能负责人/PMO；违法、安全、舞弊或 L4 重大风险立即停止受影响活动，保全原始证据并升级总经理办公会或授权负责人。例外批准必须限定事项、理由、期限和补救，不能变成长期默认做法。

## 6. 记录与归档

成果与贡献清单、源代码提交、数据/模型来源、许可证与采购授权、合同条款、保密承诺、发布审批、交付清单、离项交接和争议证据。
