# 信息安全管理制度



## 1. 目的、对象与触发



适用于公司网络、终端、账号、应用、云服务、模型、数据和供应链的安全治理，以及安全开发、访问控制、日志、漏洞、备份和事件响应。具体等保、合同或行业要求先判定适用条件。



## 2. 职责分工



法务风控中心牵头安全治理与事件协调；产品研发中心落实架构、开发和运维控制；数据/系统所有者批准访问；项目经理执行客户安全约束；人力与综合管理办理人员和资产变更；全员保护账号并报告异常。



## 3. 领域规则



- 数据和系统按业务重要性、个人信息、客户/合同要求及破坏影响分类分级，控制强度随等级提高。

- 账号实名、最小权限、按需授权，特权操作增强认证和审计；入转调离及时变更权限，共享账号仅在受控例外下使用。

- 研发环境与生产环境隔离，代码、依赖、接口、模型和配置上线前进行评审、测试和漏洞处置；密钥不得写入代码或普通文档。

- 对适用网络运营者义务的系统，按现行网络安全法第二十三条留存相关网络日志不少于六个月；更长合同或监管期限优先。

- 个人信息处理核验目的和合法性基础，遵循最小必要与最短必要保存；敏感个人信息和对外提供提高审批与安全措施。

- 备份可恢复性必须演练；安全事件按发现、隔离、保全、评估、报告、恢复和复盘闭环，未经授权不得对外披露。

- GB/T 22239-2019 等推荐性标准只在等保对象、合同采用或认证条件成立时形成具体要求。



## 4. 审批与关键控制点



- 定期复核高权限、离职账号、外部共享、漏洞、补丁、备份和日志完整性。

- 客户数据进入开发、测试或模型流程前完成授权、最小化、隔离和退出/删除设计。

- 供应商接入须限定网络、数据、人员和期限，结束后关闭账号并验证数据返还或删除。



## 5. 例外、停止与升级



- 生产故障应急权限按最小范围和时限开通，事后复核操作；紧急不豁免真实日志和责任人记录。

- 疑似泄露、密钥暴露、恶意代码、日志被删或 L4 影响时立即隔离受影响范围并升级安全负责人。



在信息安全数据治理事项中，需要跨部门裁决或达到 L3 风险时交对应职能负责人/PMO；违法、安全、舞弊或 L4 重大风险立即停止受影响活动，保全原始证据并升级总经理办公会或授权负责人。例外批准必须限定事项、理由、期限和补救，不能变成长期默认做法。



## 6. 记录与归档



资产与数据清单、分类分级、访问审批、权限复核、开发与上线记录、漏洞补丁、日志、备份演练、供应商接入、安全事件时间线和复盘。
