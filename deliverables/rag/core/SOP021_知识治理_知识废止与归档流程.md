# 知识废止与归档流程

## 触发条件与使用边界

知识失效、被新版本替代、适用业务终止、来源撤销或风险要求停止现行使用时启动。 本流程只落实上游知识 POL009, KB006, REF009，不新增金额阈值、审批权限或法律义务。

## 必要输入与完整性检查

- 废止原因、证据和拟停止日期
- 替代资产/无替代说明
- 引用、使用者、保存和法律保全要求

执行《知识废止与归档流程》前，受理人必须确认输入来源、版本、责任人和缺口。缺少会影响范围、金额、时限、合规或验收的材料时，状态保持“阻断”，退回对应责任人；允许带假设分析时须显式列出假设及不可据此作出的承诺。

## 参与角色

知识所有者提出废止；知识管理员分析引用和归档；领域负责人确认业务影响；法务/安全确认保存与删除限制；授权人批准；下游所有者完成迁移。

## 可执行步骤

1. 核验资产身份、现行版本、责任人及废止触发事实。
2. 区分整项废止、部分失效、版本替代和暂停使用，选择正确状态。
3. 盘点引用该资产的流程、问答、模板、Agent 和业务记录。
4. 确认替代知识及生效衔接；无替代时定义回答状态和人工入口。
5. 评估档案、诉讼保全、合同、个人信息与安全保存/删除要求。
6. 取得批准后在生效时点停止现行入口，添加替代/废止说明。
7. 迁移下游引用并验证检索不再把旧资产作为当前答案。
8. 将历史版本、批准、迁移和销毁/保留依据归档。

## 关键判断与分支

- 仅来源 URL 失效但规则仍有效：更换证据位置并重新验证，不直接废止知识。
- 法律保全或审计冻结：停止使用但保留不可变证据。
- 暂无替代：下游返回 UNKNOWN/OUT_OF_SCOPE 并指向责任人。

## 输出物与完成条件

- 废止/替代决定和生效时间
- 引用迁移、检索阻断与验证记录
- 归档包及保存/销毁依据

《知识废止与归档流程》的所有输出均须有责任人、审核/批准状态、版本和归档位置；只有上文列明的完成证据通过核验，流程状态才可关闭。

## 失败路径与人工升级

资产仍被关键流程使用且无迁移方案、保存义务未判断或批准链不完整时不得删除或隐藏历史证据。 其他跨部门或 L3 风险交部门负责人、PMO 或专业控制部门裁决；任何紧急处置只补真实发生记录，不得倒签或补造审批。
