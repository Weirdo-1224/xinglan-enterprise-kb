# 知识新增与审核流程



## 触发条件与使用边界



新规则、经验、参考资料或企业事实需要成为正式知识资产时启动。 本流程只落实上游知识 POL009, KB006, KB008, REF017，不新增金额阈值、审批权限或法律义务。



## 必要输入与完整性检查



- 拟发布内容、适用对象和知识类型

- 来源原文/内部依据、定位与许可

- 上游依赖、责任人、敏感级别和生效计划



执行《知识新增与审核流程》前，受理人必须确认输入来源、版本、责任人和缺口。缺少会影响范围、金额、时限、合规或验收的材料时，状态保持“阻断”，退回对应责任人；允许带假设分析时须显式列出假设及不可据此作出的承诺。



## 参与角色



内容作者整理资产；知识管理员检查结构、ID、来源和重复；领域负责人审核业务结论；法务/安全处理版权、隐私和保密；知识所有者批准发布。



## 可执行步骤



1. 作者确认这是事实、规则、流程、问答、岗位还是参考，不把不同效力内容混写。

2. 搜索现有知识，决定新增、修订或仅建立引用，避免创建语义重复资产。

3. 登记来源权威、效力、适用性、状态、日期、定位和转换方式。

4. 区分可直接引用、派生和合成的主张；合成参数标明内部属性。

5. 编写正文和元数据，建立上游/下游关系及面向 Agent 的可执行信息。

6. 领域、来源、权限和格式审核人分别给出证据化意见。

7. 解决冲突或明确 UNKNOWN/CONFLICT；不能解决的真实问题进入人工复核。

8. 批准后发布现行版本，通知下游并记录生效与复核日期。



## 关键判断与分支



- 来源只能支持部分结论：缩小声明范围，不用推断补全。

- 公开案例或他企实践：标为 ANALOGICAL，仅保留方法启示。

- 包含敏感材料：拆分公开摘要与受控证据，避免扩大访问范围。



## 输出物与完成条件



- 可检索的正式知识资产

- 完整元数据、来源血缘和声明证据

- 审核批准、发布和下游通知记录



《知识新增与审核流程》的所有输出均须有责任人、审核/批准状态、版本和归档位置；只有上文列明的完成证据通过核验，流程状态才可关闭。



## 失败路径与人工升级



来源真实性不明、适用性未判断、与 Canonical Facts 冲突、版权/保密无依据或责任人缺失时不得发布。 其他跨部门或 L3 风险交部门负责人、PMO 或专业控制部门裁决；任何紧急处置只补真实发生记录，不得倒签或补造审批。
