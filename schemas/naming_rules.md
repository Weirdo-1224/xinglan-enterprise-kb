# 命名规范

## ID 与文件名

每项知识资产必须有全局唯一 `knowledge_id` 和全局唯一 `filename`。前缀表达资产类型：`KB` 企业基础、`REF` 公开依据、`POL` 制度、`SOP` 流程、`FAQ` FAQ/规则、`ROLE` 岗位、`P###_##` 历史项目、`CASE` 跨项目案例、`TPL` 模板、`DATA` 业务数据。普通资产使用三位序号，项目资产使用项目号加两位序号。

文件名使用中文主题，禁止空格、路径分隔符、不可见字符和同名文件；Markdown 使用 `.md`，结构化数据使用声明格式对应的 `.csv`/`.xlsx`。示例：`POL001_企业制度_人力资源管理办法.md`、`P001_01_客户需求说明.md`、`DATA001_员工花名册.xlsx`。

## 版本与变更

正文元数据使用 `vMAJOR.MINOR`。兼容性修订递增 MINOR，规则或结构发生不兼容变化递增 MAJOR。已发布资产不得随意改名；如确需改名，保留旧 ID/文件名映射并在变更记录中说明。禁止复用已废弃 ID，禁止用文件名变化掩盖版本变化。

## 其他规则

ID、文件名、标题和 Canonical 术语必须保持一致。Manifest 是命名登记的唯一入口；新增、拆分、合并和归档必须先更新 Manifest，再生成正文或上传包。
